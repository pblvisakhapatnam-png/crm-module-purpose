# External Dependency Register

## Purpose

Make external-system readiness visible before a module is scheduled. A logical contract may be
approved while its adapter is blocked; the blocked dependency and fallback must not be hidden
inside an implementation prompt.

Status meanings:

```text
AVAILABLE          Current use and an implementable interface are confirmed.
INTERFACE_NEEDED   Authoritative source is known; usable interface/readiness is unconfirmed.
DECISION_NEEDED    A business/ownership choice is still open.
DESIGN_NEEDED      Product is known; repository/access/retention or operating design is open.
```

## Scheduling rule

The independent reviewer must check this register before issuing an adapter-dependent package. If status is not
`AVAILABLE`, the package must include dependency discovery/fallback scope or stop before runtime
integration. Target milestones above replace invented calendar dates; the responsible owner sets
a date when the work enters the active delivery schedule.
